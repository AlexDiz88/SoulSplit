# Create Enemy - Soul Split

Генератор дефов врагов (`EnemyDef`). По запросу сразу заводит способности кластера `враги`.

Новые юниты - только `status: "черновик"`: в боевой пул (`ENEMY_KINDS`) и боевые способности **не** пиши, пока статус не `"одобрено"`. Отказы и черновики в бой не попадают (фильтр по статусу).

## Вызов

Примеры:

- `/create-enemy Руины`
- `/create-enemy Бандиты, 5`
- `/create-enemy Служители алого ордена, 3, все в алых одеждах и с ритуальным оружием`
- `create-enemy Северная дорога, 4`
- `/create-enemy Главарь бандитов, уровень 3, reach 1, ряд 4, мини-босс, 1 способность`
- `/create-enemy Главарь бандитов, 1 способность: Раздавить - тяжёлый удар булавой по герою с оглушением`
- `/create-enemy Бандиты, 3, каждому по 1 способности`

Разбор:

1. Убери ведущий `/create-enemy` или `create-enemy`.
2. Остаток читай как свободный запрос (запятые - удобные разделители, не жёсткая схема).
3. **Тема** обязательна: регион, группа, или конкретный юнит с чертами.
4. Целое число без слова "способность" = сколько врагов сгенерировать. Числа нет и нет именного юнита - **3**. Именной юнит с чертами - пачка из **1**, если иное не сказано.
5. Запрос способности: слова вроде `способность`, `способности`, `N способностей`, `со способностью`, плюс опционально имя и описание приёма.
6. Всё остальное - обязательные особенности юнита (оружие, reach, ряды, уровень, мини-босс, внешность).

Тема пустая или двусмысленная - один вопрос, без генерации.

## Перед дизайном

1. Прочитай [regions.md](regions.md) и [format.md](format.md).
2. Прочитай [INDEX.md](../../../design/enemies/INDEX.md).
3. Прочитай **целиком** дефы целевой группы (`src/combat/enemyDefs/{group_id}/`), если папка есть.
4. По INDEX просмотри крючки других групп - для ориентира лора и ролей, не как запрет на похожесть.
5. Если нужны способности - прочитай [abilities.md](abilities.md) и при необходимости [format.md](../create-ability/format.md) / раздел "Враги" в [aspects.md](../create-ability/aspects.md). Глянь `design/abilities/INDEX.md` и папку `src/abilities/abilityDefs/enemies/`.
6. Регион / группу не подменяй молча. Нет в каноне - либо спроси один раз, либо заведи новую группу с честным `groupId`.

## Разнообразие и повторы

Мир большой: группы, квесты и лор требуют много юнитов. **Похожие и повторяющиеся враги допустимы** (тот же скелет и похожее решение в другой группе или даже рядом). Не отказывай и не "улучшай в уникальность", если пользователь просит конкретного юнита.

Ориентир внутри одной пачки за один вызов:

- по возможности разные роли / reach / силуэты, чтобы пачка читалась в бою;
- имена не совпадай с уже существующими в INDEX (новое имя - новый id);
- не выдавай два файла с одним и тем же русским именем.

Запрет "копия решения = отказ", как у способностей героя, **на врагов не распространяется**.

## Уровень и статы

У каждого врага есть **базовый уровень** (`baseLevel`). В бою движок сам бросает оффсет -2…+2 (кап 1-20) и масштабирует HP/атаку. В дефе пиши статы **на базовом уровне**, не на оффсете.

Полоса чисел - в [format.md](format.md). Ориентир региона - в [regions.md](regions.md). Не выходи из полосы без игровой причины, и эту причину формулируй как правило для игрока в `description` / `extra`, а не как заметку о балансной таблице.

## Текст для игрока

`description` - как в бестиарии классической RPG: одно-два предложения, кто это и как дерётся. Числа не повторяй.

Поле `extra` только для правила, которое игрок должен знать и которое не вошло в описание. Если такого правила нет, `extra` не добавляй. Не пиши заметки разработчика: прототип, "в коде этого нет".

## Способности

Правила создания и привязки - в [abilities.md](abilities.md). Кратко:

- По запросу создай 1+ дефов в `src/abilities/abilityDefs/enemies/` и пропиши их боевые id в `abilities` дефа (`["crushing_blow"]`).
- Пользователь описал приём - следуй описанию. Не описал - придумай под роль юнита.
- Похожие способности врагов **можно** дублировать. Можно и переиспользовать существующий id.
- Без запроса способностей большинству черновиков поле `abilities` не ставь.

## Запись

1. Составь список из N имён и ролей **до** записи файлов. Имена не совпадают с уже существующими в INDEX.
2. Если нужны новые способности - сначала (или сразу после юнита) запиши их по [abilities.md](abilities.md), потом ссылки в дефе врага.
3. Собери деф по шаблону из [format.md](format.md).
4. Сохрани в `src/combat/enemyDefs/{groupId}/{id}.ts`. `id` и имя файла - **snake_case**, уникальный в каталоге. `groupId` - kebab/snake как у папки (`bandits`, `undead`).
5. Портрет-заглушка. Английское имя файла = id: `goblin_spear.png`. Скопируй `assets/art/enemies/no_image.png` в `assets/art/enemies/{id}.png`. Если файл уже есть - не затирай. В деф: `portrait: "{id}.png"`.
6. В ответе пользователю всегда указывай английский id и имя файла портрета (и id/иконку каждой новой способности). При смене русского названия синхронно меняй id (см. `.cursor/rules/id-rename.mdc`; для способностей - `ability-rename.mdc`).
7. Допиши строку в INDEX врагов. Крючок = поле `hook` дефа.
8. Статус нового юнита - `"черновик"`. Юниты со статусом `"одобрено"`, `"отказ"` или `"под вопросом"` генератор сам не меняет (кроме явного запроса пользователя одобрить / отказать).

Бестиарий и бой читают эти дефы напрямую. Отдельный импорт в `enemies.ts` / `portraits.ts` **не нужен** (glob + резолвер портретов). Пулы локаций (`regions.ts`) этим скиллом не обновляй без запроса.

Между юнитами подтверждения не спрашивай.

## Одобрение → боевой пул

Когда пользователь **одобряет** врага:

1. В дефе: `status: "одобрено"` + строка в `design/enemies/INDEX.md`.
2. `ENEMY_KINDS` подхватит юнита сам. Не копируй статы в `enemies.ts`.
3. Портрет уже через `portrait` + файл в `assets/art/enemies/`. Нет арта - `no_image.png`, файл портрета не затирай.
4. `abilities`: если id уже есть в боевом каталоге способностей - ок. Если способности ещё нет в коде боя - либо добавь по правилам способностей врагов, либо оставь без `abilities` и явно скажи в ответе (карточка способности в design остаётся).
5. Статус `"отказ"` / снятие одобрения: поменяй `status` в дефе и вычисти ссылки в `zones` / пулах, если были. Из `ENEMY_KINDS` убирать вручную не нужно.

Черновик и `"под вопросом"` в боевой пул не попадают.

## Ответ в чате

Не разворачивай пачку полных дефов. Таблица: название, группа, ур., крючок, файл. Полный текст только в файлах.

Если создавались способности - вторая таблица: способность, тип, крючок, файл, юнит.

В конце коротко: сколько врагов (и способностей) создано, тема, пути к INDEX врагов и при необходимости способностей.
