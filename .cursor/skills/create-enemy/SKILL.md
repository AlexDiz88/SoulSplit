# Create Enemy - Soul Split

Генератор карточек врагов для бестиария. По запросу сразу заводит способности кластера `враги`.

Новые карточки - только `черновик`: в боевой пул (`ENEMY_KINDS`) и боевые способности **не** пиши, пока статус не `одобрено`. Отказы и черновики в код не попадают.

## Вызов

Примеры:

- `/create-enemy Руины`
- `/create-enemy Бандиты, 5`
- `/create-enemy Служители алого ордена, 3, все в алых одеждах и с ритуальным оружием`
- `create-enemy Северная дорога, 4`
- `/create-enemy Главарь бандитов, уровень 3, reach 1, ряд 4, мини-босс, 1 способность`
- `/create-enemy Главарь бандитов, 1 способность: Раздавить - тяжёлый удар булавой по герою с оглушением`
- `/create-enemy Бандиты, 3, каждому по 1 способности`

Разбор:

1. Убери ведущий `/create-enemy` или `create-enemy`.
2. Остаток читай как свободный запрос (запятые - удобные разделители, не жёсткая схема).
3. **Тема** обязательна: регион, группа, или конкретный юнит с чертами.
4. Целое число без слова "способность" = сколько врагов сгенерировать. Числа нет и нет именного юнита - **3**. Именной юнит с чертами - пачка из **1**, если иное не сказано.
5. Запрос способности: слова вроде `способность`, `способности`, `N способностей`, `со способностью`, плюс опционально имя и описание приёма.
6. Всё остальное - обязательные особенности юнита (оружие, reach, ряды, уровень, мини-босс, внешность).

Тема пустая или двусмысленная - один вопрос, без генерации.

## Перед дизайном

1. Прочитай [regions.md](regions.md) и [format.md](format.md).
2. Прочитай [INDEX.md](../../../design/enemies/INDEX.md).
3. Прочитай **целиком** карточки целевой группы (`design/enemies/{group_id}/`), если папка есть.
4. По INDEX просмотри крючки других групп - для ориентира лора и ролей, не как запрет на похожесть.
5. Если нужны способности - прочитай [abilities.md](abilities.md) и при необходимости [format.md](../create-ability/format.md) / раздел "Враги" в [aspects.md](../create-ability/aspects.md). Глянь `design/abilities/INDEX.md` и папку `design/abilities/enemies/`.
6. Регион / группу не подменяй молча. Нет в каноне - либо спроси один раз, либо заведи новую группу с честным `group_id`.

## Разнообразие и повторы

Мир большой: группы, квесты и лор требуют много юнитов. **Похожие и повторяющиеся враги допустимы** (тот же скелет и похожее решение в другой группе или даже рядом). Не отказывай и не "улучшай в уникальность", если пользователь просит конкретного юнита.

Ориентир внутри одной пачки за один вызов:

- по возможности разные роли / reach / силуэты, чтобы пачка читалась в бою;
- имена не совпадай с уже существующими в INDEX (новое имя - новый id);
- не выдавай два файла с одним и тем же русским именем.

Запрет "копия решения = отказ", как у способностей героя, **на врагов не распространяется**.

## Уровень и статы

У каждого врага есть **базовый уровень** (поле бестиария). В бою движок сам бросает оффсет -2…+2 (кап 1-20) и масштабирует HP/атаку. В карточке пиши статы **на базовом уровне**, не на оффсете.

Полоса чисел - в [format.md](format.md). Ориентир региона - в [regions.md](regions.md). Не выходи из полосы без игровой причины, и эту причину формулируй как правило для игрока в **Описание** / **Доп**, а не как заметку о балансной таблице.

## Текст для игрока

Описание - как в бестиарии классической RPG: одно-два предложения, кто это и как дерётся. Числа не повторяй.

Поле **Доп** только для правила, которое игрок должен знать и которое не вошло в описание. Если такого правила нет, **Доп** не добавляй. Не пиши заметки разработчика: прототип, "в коде этого нет".

## Способности

Правила создания и привязки - в [abilities.md](abilities.md). Кратко:

- По запросу создай 1+ карточек в `design/abilities/enemies/` и пропиши их id в поле **Способности** врага.
- Пользователь описал приём - следуй описанию. Не описал - придумай под роль юнита.
- Похожие способности врагов **можно** дублировать. Можно и переиспользовать существующий id.
- Без запроса способностей большинству черновиков ставь `нет`.

## Запись

1. Составь список из N имён и ролей **до** записи файлов. Имена не совпадают с уже существующими в INDEX.
2. Если нужны новые способности - сначала (или сразу после юнита) запиши их по [abilities.md](abilities.md), потом ссылки в карточке врага.
3. Собери карточку врага по шаблону из [format.md](format.md).
4. Сохрани в `design/enemies/{group_id}/{id}.md`. `id` - латиница, kebab-case, уникальный в каталоге. `group_id` - kebab-case.
5. Портрет-заглушка. Английское имя файла - `id` через подчёркивания: `goblin-spear` → `goblin_spear.png`. Скопируй `assets/art/enemies/no_image.png` в `assets/art/enemies/{имя}.png`. Если файл уже есть - не затирай. В шапку карточки запиши `portrait: {имя}.png`.
6. В ответе пользователю всегда указывай английский id и имя файла портрета (и id/иконку каждой новой способности). При смене русского названия синхронно меняй id (см. `.cursor/rules/id-rename.mdc`; для способностей - `ability-rename.mdc`).
7. Допиши строку в INDEX врагов. Крючок: reach/ряды и роль/решение (для навигации, не как антидубль).
8. Статус новой карточки - `черновик`. Карточки со статусом `одобрено`, `отказ` или `под вопросом` генератор сам не меняет (кроме явного запроса пользователя одобрить / отказать).

Бестиарий в игре читает эти карточки и `portrait`. Формат не ломай. Пулы локаций (`zones.ts`) этим скиллом не обновляй без запроса.

Между карточками подтверждения не спрашивай.

## Одобрение → боевой пул

Когда пользователь **одобряет** врага (статус карточки / строки INDEX → `одобрено`), **обязательно** синхронно зарегистрируй его в игре:

1. Карточка: `status: одобрено` + строка в `design/enemies/INDEX.md`.
2. `EnemyKind` в [`src/combat/enemies.ts`](../../../src/combat/enemies.ts) (`ENEMY_KINDS`):
   - `id` - snake_case (`bandit-vagabond` → `bandit_vagabond`);
   - статы, reach, `spawnRows`, weapon, aspect, `baseLevel` - из карточки;
   - мини-босс / босс: при необходимости `threatMult` (обычно `1.5`);
   - `portraitUrl: PORTRAIT_URLS.<id>`.
3. Портрет в [`src/art/portraits.ts`](../../../src/art/portraits.ts): импорт файла из `assets/art/enemies/` и ключ в `PORTRAIT_URLS`. Нет арта - `no_image.png`, файл портрета не затирай.
4. Способности из карточки: если id уже есть в боевом каталоге способностей - пропиши в `abilities` у kind. Если способности ещё нет в коде боя - либо добавь по правилам способностей врагов, либо оставь без `abilities` и явно скажи в ответе (карточка способности в design остаётся).
5. Статус `отказ` / снятие одобрения: из `ENEMY_KINDS` и `PORTRAIT_URLS` убери (и вычисти ссылки в `zones` / пулах, если были).

Черновик и `под вопросом` в боевой пул не добавляй.

## Ответ в чате

Не разворачивай пачку полных карточек. Таблица: название, группа, ур., крючок, файл. Полный текст только в файлах.

Если создавались способности - вторая таблица: способность, тип, крючок, файл, юнит.

В конце коротко: сколько врагов (и способностей) создано, тема, пути к INDEX врагов и при необходимости способностей.
