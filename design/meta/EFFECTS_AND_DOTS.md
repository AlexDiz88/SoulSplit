# Эффекты, DoT и универсальные триггеры

**Статус: одобрено.** Канон для карточек способностей, лута и боя. Цель: **любая пара аспектов играбельна**, нет супер-пар, эксперименты не упираются в таблицу 20×20.

См. также столбы школ: [ASPECTS.md](./ASPECTS.md). Генератор карточек: `.cursor/skills/create-ability/` (format.md, SKILL.md).

## Слои (как думать о эффекте)

| Слой | Назначение | Пример |
|------|------------|--------|
| **Урон способности** | Скейл по `aspect` этой карточки + статы | огненный шар, звериный укус |
| **DoT на цели** | Давление во времени, **слоты по источнику** (см. ниже) | горение, яд, кровотечение |
| **Бафф / дебафф способности** | Один именованный пакет от **одной** кнопки | "Хватка корней", "Скорость ветра" |
| **Универсальные условия** | Триггеры для способностей **любых** пар | «есть любой DoT», «есть любой дебафф» |

Усилители **только своей школы** (шок → урон **Молнии**, метка добычи → **Дух Зверя**) не делают пару сильнее других пар - они усиливают **одну кнопку** этой школы.

## Правило: 1 способность = 1 иконка-пакет

**Канон для дизайна и UI.**

- Одна способность даёт **одну** иконку баффа/дебаффа на цель (пакет привязан к способности: имя, иконка, один таймер).
- Пакет **может содержать несколько эффектов** сразу (удержание + DoT + замедление атаки и т.д.) - это грани **одного** эффекта способности, не несколько иконок и не несколько слотов для `any_debuff` / `any_buff`.
- Пакет **может смешивать усиление и ослабление** в одной иконке (tradeoff). Пример: "+20% к наносимому урону и +5% к получаемому урону на 5 с" - **одна** иконка способности, в тултипе оба эффекта; рамка UI - **смешанная** (не две иконки "бафф" + "дебафф").
- **Запрещено** две независимые иконки / два пакета от одной кнопки.
- Примеры чистых пакетов: **Хватка корней** (дебафф: корни + урон/с + реже бьёт); **Скорость ветра** (бафф: быстрее автоатаки).

Внутренний код боя может хранить несколько `kind` для механики; **отображение и дизайн-карточки** всегда говорят об одном пакете способности.

## Универсальность (задумка игрока)

Способности и (позже) аффиксы могут проверять:

- **`any_dot`** - на цели активен хотя бы один DoT (от способности или предмета).
- **`any_debuff`** - на цели активен хотя бы один дебафф **не из категории DoT** (slow, root, stun, шок, метки, −atk, промах и т.д.) **или** отдельное правило «дебафф включая DoT» - задаётся в карточке явно.

Пример оформления в **Числа** карточки: «+12% урона по цели с **любым DoT**» (не привязка к яду/огню).

Бонус держать **умеренным**, чтобы solo-aspect и non-DoT билды не проигрывали; универсальный бонус - **опция** в ротации, не обязательный костыль для пар.

## DoT: модель (основная)

1. **От героя - не больше двух DoT одновременно на одной цели**, по одному **на активный аспект**:
   - DoT от способности с `aspect_id` основного аспекта занимает **слот A**;
   - DoT от вторичного аспекта - **слот B**;
   - новый DoT **той же школы** (другая способность) **заменяет/обновляет** слот этой школы (potency/duration по правилам карточки, без второго параллельного следа от той же школы).

2. **Фамилия DoT (лор и иконка)** - огонь→горение, природа→яд, кровь→кровотечение, алхимия→кислота, колдовство→порча и т.д. Две школы **не усиливают одну фамилию** вторым слоем: в UI может быть одна иконка «кровотечение», но на цели **два слота** только если это DoT **разных аспектов** (слот A и B), а не два стака одной механики.

3. **Одинаковая фамилия с двух аспектов** (кровь + скрытность, оба bleed): **не суммировать** potency в один супер-bleed. Работают **два независимых слота** (A и B) с **своими** potency/duration; универсальный триггер `any_dot` срабатывает один раз. DoT-способности в школах с общей фамилией проектировать **слабее**, чем уникальные DoT (горение только у огня).

4. **Предметы и автоатака** - **слоты экипировки**, не смешивать со слотами A/B:
   - **слот M** (mainhand proc), **слот O** (offhand proc);
   - опционально **слот G** (глобальный аффикс брони/кольца);
   - procs **не повышают** potency DoT способности; **refresh** только **свой** слот;
   - `any_dot` учитывает и слоты M/O/G.

5. **Классификация «магический / физический DoT»** - только для **резистов** и текста, **не** для запрета пар и **не** для суммирования. Универсальные триггеры - по **`any_dot`**, не по классу.

6. **Катализ (алхимия)** - переплавка **любого** DoT в кислоту по правилам карточки; не бонус «яд природы + алхимия».

## DoT от предметов (UI)

- На портрете врага: **до 2 иконок DoT от героя** + **1 иконка «от оружия»** (тултип: main/off, числа отдельно).
- Тултип: источники, **свой** остаток времени и **свой** урон/с на строку.
- Подсказка способности: DoT от **этого** умения = слот школы этой карточки.

Внутри боя допустимо **N записей** в данных; **отображение** - сгруппированное.

## Дебаффы и метки

- Пакет дебаффа/баффа = **способность** (см. правило выше). Метки школы (добыча, охота, шок) - тоже пакеты своих способностей / аффиксов, не россыпь иконок-кондиций.
- **`any_debuff`** считает **пакеты** (один скилл = один), без требования конкретной школы; в карточке явно: учитывать ли DoT-пакет как дебафф.
- Внутренние kind (slow/root/stun и т.д.): на цели один dominant по kind для механики - **больший potency**, **больший срок**, если карточка не вводит stackable. Это не оправдание нескольких UI-иконок от одной способности.

## Чеклист для новой карточки

1. Бафф/дебафф: **один пакет на способность** (одна иконка; внутри можно несколько эффектов, в т.ч. усиление+ослабление)? Не плодить вторую иконку с той же кнопки.
2. DoT даёт? **aspect_id** → слот A/B, **фамилия** для UI (часто DoT = тот же пакет, что и дебафф способности).
3. Усиливает только **свою школу** или **`any_dot` / `any_debuff`**?
4. Заменяет DoT **той же школы** на цели?
5. Stackable kind vs refresh-only - **Доп** при необходимости.

## Глобальные vs боевые эффекты

Два независимых слоя:

| Слой | Где живёт | Когда тикает | После боя |
|------|-----------|--------------|-----------|
| **Глобальные** | `HeroProfile.globalEffects` | только вне боя (город / карта) | остаются |
| **Боевые** | `Unit.statuses` (`StatusEffect`) | только в бою | сбрасываются (не сериализуются) |

Глобальные действуют только на героя (других юнитов вне боя нет). Пример: **Восстановление сил** - только в городе +1 HP и +1 маны/с, бесконечно; иконка в левом верхнем углу города; при выходе на карту эффект снимается.

Боевые баффы/дебаффы:

- **Враги и суммоны:** компактные иконки **под карточкой**; рамка: зелёная = бафф, красная = дебафф, янтарная = смешанный пакет (усиление + ослабление); таймер `ceil(remaining)`, до 4 видимых + `+N`.
- **Герой:** те же данные, иконки **крупнее**; чистые баффы и смешанные (tradeoff на себя) **слева** от HP/мана, чистые дебаффы **справа**.
- **Одна иконка на пакет способности** (`sourceAbilityId`); несколько внутренних `kind` от одного скилла **сворачиваются** в одну иконку. Без `sourceAbilityId` - fallback по `kind`.

Код: `src/effects/globalEffects.ts`, `src/effects/combatStatusMeta.ts`, `src/combat/StatusIconStrip.ts`, `src/ui/globalEffectsHud.ts`.

## Реализация в коде

Поэтапно: слоты DoT, группировка UI, `any_dot` / `any_debuff` в расчёте урона. Прототип пока использует упрощённые `kind` (`burn`, `bleed`, `poison`); новые карточки пишутся уже под этот канон. UI полярности и таймеров уже в бою.
