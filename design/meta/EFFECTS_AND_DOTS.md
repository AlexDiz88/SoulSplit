# Эффекты, DoT и универсальные триггеры

Черновик канона для карточек способностей, лута и боя. Цель: **любая пара аспектов играбельна**, нет супер-пар, эксперименты не упираются в таблицу 20×20.

## Слои (как думать о эффекте)

| Слой | Назначение | Пример |
|------|------------|--------|
| **Урон способности** | Скейл по `aspect` этой карточки + статы | огненный шар, звериный укус |
| **DoT на цели** | Давление во времени, **слоты по источнику** (см. ниже) | горение, яд, кровотечение |
| **Дебафф (не DoT)** | Контроль, ослабление, метки школы | slow, шок, метка добычи |
| **Универсальные условия** | Триггеры для способностей **любых** пар | «есть любой DoT», «есть любой дебафф» |

Усилители **только своей школы** (шок → урон **Молнии**, метка добычи → **Дух Зверя**) не делают пару сильнее других пар - они усиливают **одну кнопку** этой школы.

## Универсальность (задумка игрока)

Способности и (позже) аффиксы могут проверять:

- **`any_dot`** - на цели активен хотя бы один DoT (от способности или предмета).
- **`any_debuff`** - на цели активен хотя бы один дебафф **не из категории DoT** (slow, root, stun, шок, метки, −atk, промах и т.д.) **или** отдельное правило «дебафф включая DoT» - задаётся в карточке явно.

Пример оформления в **Числа** карточки: «+12% урона по цели с **любым DoT**» (не привязка к яду/огню).

Бонус держать **умеренным**, чтобы solo-aspect и non-DoT билды не проигрывали; универсальный бонус - **опция** в ротации, не обязательный костыль для пар.

## DoT: рекомендованная модель

### Проблема

- Общий канал (два аспекта кровотечения **складываются**) → пары **Кровь + Сила/Скрытность** сильнее остальных на DoT-билде.
- Отдельный DoT на каждый из 20 аспектов → тяжёлый UI и резисты, но **честно для dual-aspect** (макс. 2 типа от героя).
- Классы «магический / физический DoT» → cross-class пара кажется слабее на одном DoT-билде, но игрок **не обязан** играть через DoT; из ~190 пар остаётся много валидных.

### Решение: **слот DoT на источник**, **фамилия** для UI, **флаг `any_dot` для логики**

1. **От героя - не больше двух DoT одновременно на одной цели**, по одному **на активный аспект**:
   - DoT от способности с `aspect_id` основного аспекта занимает **слот A**;
   - DoT от вторичного аспекта - **слот B**;
   - новый DoT **той же школы** (другая способность) **заменяет/обновляет** слот этой школы (potency/duration по правилам карточки, без второго параллельного следа от той же школы).

2. **Фамилия DoT (лор и иконка)** - огонь→горение, природа→яд, кровь→кровотечение, алхимия→кислота, колдовство→порча и т.д. Две школы **не усиливают одну фамилию** вторым слоем: у **Крови** и **Скрытности** в UI может быть одна иконка «кровотечение», но на цели **два слота** только если это DoT **разных аспектов** (слот A и B), а не два стака одной механики.

3. **Одинаковая фамилия с двух аспектов** (кровь + скрытность, оба bleed): **не суммировать** potency в один супер-bleed. Работают **два независимых слота** (A и B) с **своими** potency/duration; универсальный триггер `any_dot` срабатывает один раз. Для баланса числа DoT-способностей в таких школах проектировать **слабее**, чем уникальные DoT (горение только у огня).

4. **Предметы и автоатака** - **слоты экипировки**, не смешивать со слотами A/B без правила:
   - **слот M** (mainhand proc), **слот O** (offhand proc);
   - опционально **слот G** (глобальный аффикс брони/кольца) - один общий «proc с предмета», если нужно упростить;
   - procs **не повышают** potency DoT способности; **refresh** только **свой** слот;
   - `any_dot` учитывает и слоты M/O/G.

5. **Классификация «магический / физический DoT»** - только для **резистов** и текста, **не** для запрета пар и **не** для суммирования. Универсальные триггеры - по **`any_dot`**, не по классу.

6. **Катализ (алхимия)** - переплавка **любого** DoT в кислоту по правилам карточки; не бонус «яд природы + алхимия».

### Почему это лучше альтернатив

| Подход | Итог |
|--------|------|
| Суммирование одной фамилии (bleed+bleed) | Супер-пары, отказ |
| 20 уникальных DoT без слотов | Перегруз UI, но dual OK; решается слотами A/B + equip |
| Только 2 класса mag/phys | DoT-билд режет половину пар; приемлемо как **опция**, не как канон боли |
| **Слоты: 2 аспекта + экипировка**, фамилия для UI, `any_dot` | Пары равны; DoT-билд осознанно выбирает 2 школы с DoT или 1 DoT + burst; предметы добавляют proc без слияния с кнопкой |

## DoT от предметов (UI)

Игрок не обязан видеть три отдельных таймера «кровотечение» без пояснения.

**Рекомендация UI:**

- На портрете врага: **до 2 иконок DoT от героя** (подпись школы или фамилии: «яд», «горение») + **1 иконка «от оружия»** (если активен proc), если обе руки - **одна** «от оружия» с **тултипом** (main/off, числа отдельно).
- Тултип: список источников (способность / правая / левая), **свой** остаток времени и **свой** урон/с на каждую строку.
- Для **способности** в подсказке на панели героя: «DoT на цели от **этого** умения» - брать только слот школы, если источник = эта карточка.

Внутри боя допустимо **N записей** в данных; **отображение** - сгруппированное.

## Дебаффы и метки

- **Метки школы** (добыча, охота, шок) - отдельные kind, правила стаков из карточки.
- **`any_debuff`** для способностей - контроль и ослабления **без** требования конкретной школы; в карточке явно: учитывать ли DoT как дебафф.
- Slow/root/stun: по возможности **один dominant** на kind (как в прототипе: max potency, max duration), unless карточка вводит stackable kind.

## Чеклист для новой карточки

1. DoT даёт? Какой **aspect_id** → какой **слот** (A/B) и **фамилия** для UI.
2. Усиливает только свою школу или проверяет **`any_dot` / `any_debuff`**?
3. Заменяет ли другой DoT **той же школы** на цели?
4. Есть ли **Доп** для stackable (шок) vs refresh-only (горение).

## Статус

Черновик для утверждения. После «да» - синхронизировать генератор карточек и поэтапно бой (`StatusEffect`, группировка DoT, `any_dot` в расчёте урона).
